SPHEREAI CONTEXT FOR AGENTS
============================
Updated: 2026-09-18

PROJECT
-------
SphereAI is the emotional intelligence subsystem of LifeSphere, an autonomous caregiving
ecosystem for elderly and vulnerable people. LifeSphere has five subsystems: Vital32
(biometric wearable), HollowRover (autonomous rover), EntryGuard (perimeter security),
HollowCore (home automation), SphereAI (emotional intelligence). All share a Firebase
Realtime Database backend (project: hollow-core).

SphereAI is NOT a chatbot. It fuses language, voice, and biological signals to understand
emotional state and respond like a compassionate therapist. It never directly controls
hardware. All hardware actions are structured events routed through SphereCore (Flutter
app) via Firebase.

DEADLINE: Flight Sep 30 2026. Demo Oct 2 2026. Prototype must freeze before flight.

PIPELINE (fully implemented and working)
-----------------------------------------
text -> LanguageAgent -> BiologyAgent -> VoiceAgent(mock) -> EmotionalFusion
     -> EmotionalAgent -> ResponseAgent -> SphereCoreClient(Firebase)

INTERFACES
----------
CLI:  python main.py                          (Firebase login prompt, auto-saves creds to .env)
Web:  python web_demo/app.py                  (localhost:5050, terminal aesthetic UI)
Test: venv/bin/python -m pytest tests/        (14 passing, no network required)

ARCHITECTURE RULES
------------------
1. SphereAI never controls hardware directly. Emits structured action dicts only.
2. Agents are perception-only. LanguageAgent/BiologyAgent/VoiceAgent do NOT generate replies.
3. EmotionalAgent is the ONLY layer that makes psychological interpretations.
4. ResponseAgent generates the reply using EmotionalState + LanguageResult.
5. BiologyAgent uses deterministic threshold logic only. No LLM.
6. All Gemini calls go through core/gemini.py which auto-retries all fallback models on 503.

DATA CONTRACTS
--------------
LanguageResult:   intent(constrained to 7 values), emotion, emotional_context, confidence, entities, raw_text
VitalSigns:       heart_rate, spo2, skin_temperature, activity(0.0-1.0 normalized)
BiologyResult:    vitals, heart_rate_elevated, spo2_low, temperature_abnormal, activity_level, stress_indicators, source
VoiceResult:      pitch_mean, energy, speaking_rate, tremor, long_pauses, source
FusedState:       arousal(0-1), valence(-1 to 1), convergence(0-3), dominant_emotion, emotional_context
EmotionalState:   label, arousal, valence, convergence, confidence, needs_support, alert_level
ResponseResult:   reply(str), action(dict or None)

ESP32-S3 AUDIO BRIDGE (Prompt 2)
---------------------------------
SPHEREAI_AUDIO env var: "laptop" (default) uses sounddevice mic + pyttsx3 speaker on the host.
                         "esp"    routes all audio through the ESP32-S3 over USB serial.

ESP_AUDIO_PORT:  override serial port (e.g. /dev/ttyACM0). Auto-detected from VIDs 303A/10C4/1A86
                 when exactly one matching port is present. Required if multiple ESP boards attached.
ESP_MIC_GAIN:    float multiplier applied to raw mic samples after DC removal (default 1.0).
                 Raise to 4 or 8 if mic is very quiet.
ESP_SPK_VOLUME:  float 0–1 applied before PCM encoding sent to speaker (default 0.8).

SERIAL PROTOCOL (921600 baud, USB CDC)
  Host sends  ->  Device replies
  PING        ->  PONG
  REC <ms>    ->  AUD <nbytes>, then nbytes PCM (16 kHz 16-bit LE mono), then OK
  PLAY <n>    ->  RDY, host sends n bytes in <=1024 chunks, device acks each with "K", ends DONE
  (idle)      ->  EVT BTN  (debounced BOOT button press on GPIO 0)

PIN ASSIGNMENTS (INMP441 mic / MAX98357A amp, confirmed wired)
  PIN_MIC_BCLK=5  PIN_MIC_WS=4  PIN_MIC_DIN=6  (I2S_NUM_1, left channel, L/R tied to GND)
  PIN_AMP_BCLK=15 PIN_AMP_LRC=16 PIN_AMP_DIN=7  (I2S_NUM_0, stereo frame, L=R)
  PIN_BTN=0       (BOOT button, active low, INPUT_PULLUP, 250 ms debounce)
  To change any pin: edit only firmware/sphereai_audio/config.h
