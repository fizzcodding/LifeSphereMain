SPHEREAI CONTEXT FOR AGENTS
============================
Updated: 2026-10-10

PROJECT
-------
SphereAI is the emotional intelligence subsystem of LifeSphere, an autonomous caregiving
ecosystem for elderly and vulnerable people. LifeSphere has five subsystems: Vital32
(biometric wearable), HollowRover (autonomous rover), EntryGuard (perimeter security),
HollowCore (home automation), SphereAI (emotional intelligence). All share a Firebase
Realtime Database backend (project: hollow-core).

SphereAI is NOT a chatbot. It fuses language, voice, and biological signals to understand
emotional state and respond like a compassionate therapist. It never directly controls
hardware. All hardware actions are structured events routed through SphereCore (Flutter
app) via Firebase.

PIPELINE (fully implemented and working)
-----------------------------------------
text -> LanguageAgent -> BiologyAgent -> VoiceAgent(mock) -> EmotionalFusion
     -> EmotionalAgent -> ResponseAgent -> SphereCoreClient(Firebase)

INTERFACES
----------
CLI:  python main.py                          (reads FIREBASE_EMAIL from .env, getpass prompt if absent)
Web:  python web_demo/app.py                  (127.0.0.1:5050, terminal aesthetic UI, debug=False)
Test: venv/bin/pytest tests/                  (37 passing in test_agents.py + 6 in test_voice_real.py)

SECURITY
--------
Credentials: Never saved to .env by the app. Set FIREBASE_EMAIL and FIREBASE_WEB_API_KEY
  in .env manually. Password is prompted via getpass each session.
Session cookies: HTTPONLY=True, SAMESITE=Lax.
Input: All user text wrapped in <USER_INPUT> delimiters before LLM calls.
Response action: Built deterministically from lang_result.intent, never from LLM output.
Crisis override: Deterministic keyword + emotion check in core/crisis.py triggers warm
  crisis response and write_alert to Firebase regardless of emotional label.

ENV VARS REQUIRED
-----------------
GEMINI_API_KEY          - Gemini API key
GEMINI_MODEL            - primary model (e.g. gemini-2.0-flash)
GEMINI_FALLBACK         - first fallback
GEMINI_FALLBACKS        - second fallback
GEMINI_FALLBACKT        - third fallback
FIREBASE_EMAIL          - Firebase account email for SphereAI
FIREBASE_WEB_API_KEY    - Firebase project web API key
CRISIS_EMERGENCY_NUMBER - emergency number shown in crisis response (default: 999)

BIOLOGY NOTES
-------------
VitalSigns.heart_rate, spo2, skin_temperature are all Optional[float].
None means unknown/unavailable - never flagged, never faked.
skin_temperature range for wrist MLX90614: 31.0 to 35.5 C.
mock_vitals() uses skin_temperature=34.2 (in wrist range).
spo2_low only fires when spo2 is a positive non-None float.
bio-critical override: HR > 130 or SpO2 < 90 forces arousal >= 0.7
  and convergence >= 2 in EmotionalFusion, and alert_level >= medium
  in EmotionalAgent, regardless of language signal.

VITALS FROM FIREBASE
--------------------
get_vitals() does ONE GET on vital32/ node (not 4 sequential requests).
Stale data rejection: if status/server_ts is older than 30s, returns None.
On 401: re-authenticates once and retries.
write_alert(level, label, message) writes to users/{uid}/alerts.

KNOWN LIMITATIONS
-----------------
- Voice agent is mock only (real mic path not implemented for hardware)
- Gemini calls have no hard wall-clock timeout (SDK does not expose one directly)
- Firebase idToken expires after ~1h; SphereCoreClient.authenticate() re-runs on expiry
